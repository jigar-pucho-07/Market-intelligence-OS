### What holds (checked, no finding)
- **Identity.** It comes from the session only. `currentUser` takes the SHA-256 of an opaque 32-byte HttpOnly cookie token, joins it with `is_active` and checks expiry. runAction strips `_*` keys and overwrites `user` from the session. The flows never use `_who` for anything beyond labels.
- **Pages and actions.** The page checks session → role → page map, with a 404 or a redirect home (`[[...path]]/page.tsx`). runAction checks role → action key (subscriber: none). Users & roles are admin-only, self-change is refused, the last admin is protected, and sessions are revoked on deactivation, role change and password change. The db review (A2/A3, `verify.mjs` 89 PASS) observed that a subscriber gets only `published_reports` + `news_articles`, with no phone number in the HTML or RSC payloads.
- **Passwords and sign-in.** argon2id 19 MiB/2/1, a dummy verify for unknown accounts, and per-account rate limiting. Per-address limiting only with `TRUST_PROXY_HOPS` (Owner action 7).
- **SQL.** All values go through `$n` placeholders. Identifiers come from the generated entity map. S2 passed.
- **XSS.** MarketBrief and every custom view render database and AI text as React text children: no raw HTML, no `innerHTML`. Every `target=_blank` has `rel="noopener noreferrer"`/`noreferrer`.
- **Secrets.** No secret in source, flow JSON or `.next/static` (S4/S4b/S5 passed; 0 source maps in `.next/static`). `.env` and `.env.*` are git-ignored; only `.env.example` (placeholders) is tracked. Every flow constants node holds `SET_IN_STUDIO_*` placeholders, never a value.
- **Flow writes.** Every `/api/data` and `/api/jobs` call in all six flows carries `Authorization: Bearer {{step_constants['inbound_token']}}` (W9 holds).
- **Flow responses.** They return only named plan fields, never a whole step output or a stack trace.
- **AI prompt.** It is under the DATA RULE. News sits in a `<News>` fence, with `</News>` stripped from titles and summaries. RSS markup is stripped. `parseModel` keeps only MODEL_KEYS, enum-checks the enums, caps lengths and drops advice-shaped text.
- **Dependencies.** `npm audit --omit=dev`: 0 vulnerabilities (156 production dependencies). next 16.3.8, react 19.3.0. S6 passed.
- **Seed guard.** `db.mjs seed` refuses a database that is not `*_dev`/`*_demo`, or one reached through `DB_HOST`.

## Owner actions (a person must do these)
1. **Webhook URLs are secrets until SA-01–SA-04 ship.** Limit Studio workspace membership to the people who build these flows. The URLs and inbound tokens sit in plain text in the constants nodes. Re-publish a flow (new URL) and update `WEBHOOK_<FLOW>` and the other flows' constants whenever someone with access leaves. 2. **Inbound tokens.** One per flow, in the CP Portal environment: `INBOUND_TOKEN_BROADCAST`, `INBOUND_TOKEN_MARKET_STORE`, `INBOUND_TOKEN_MARKET_PUBLISH`, `INBOUND_TOKEN_DAILY_WATCHDOG`. 4. **`DB_SSL_CA`.** Set the Pucho DB CA bundle (PEM) and confirm the start-up line reads `ssl verified`. Keep port 5432 private (`nc -zv <db-host> 5432` from outside must fail).
5. **`AUTH_PEPPER`.** Set 32 random bytes in the portal environment. The local `.env` value must not be reused.
6. **`APP_ORIGIN`.** Set it to `https://<domain>`. This turns on the `__Host-session` cookie, HSTS and the http→https redirect. Check with `curl -I` and in devtools (HttpOnly, Secure, SameSite=Lax).

8. **Database roles on the client DB.** Run `CREATE USER <app_login> WITH PASSWORD '…' IN ROLE app;` and point `DB_USER` at it, not at the schema owner. Do **not** create a `studio_reader` login: no flow uses the postgres tool (see SA-10). If roles cannot be created (Q5), record it in Known-broken.
