### What holds (checked, no finding)
- **The gate is first on every webhook path.** In all five webhook flows the step right after the trigger is `step_constants`, and nothing reads, fetches, writes or calls AI before the auth router. Both schedule flows are trigger-only (no webhook). `secretMatches` compares in time that depends only on the configured secret's length, refuses a placeholder or a secret under 16 characters, and never returns the flow's own secret (`const { webhook_secret, ...rest } = C`). `continueOnFailure` is false on every `step_constants`.
- **Flow-to-flow calls carry the callee's secret.** DAILY_SCHEDULE→MARKET_REPORT, MARKET_REPORT→MARKET_ANALYSE, MARKET_ANALYSE→MARKET_STORE, MARKET_STORE / DAILY_WATCHDOG→BROADCAST and BROADCAST→MARKET_PUBLISH each send `queryParams.k = {{step_constants['<callee>_secret']}}`. All of them are `SET_IN_STUDIO_*` placeholders.
- **No secret in Return bodies or CHECKLISTs.** Every Return names its fields; none echoes `step_constants`, a trigger, or a step output. The CHECKLISTs show `?k=<secret>` and the placeholder names only. No secret-shaped `k=` value is anywhere in the repository.
- **Alert text provenance.** Alert text is the Failed row's `Error_Message`, which the flow writes (or an analyst writes through SA-06), or the fixed `watchdogText`. It is never caller text. `clean()` collapses whitespace and cuts the text to 160 characters.
- **isAdvice coverage on the flow side.** parseModel covers the model's answer. sanitizeReportRow covers every TEXT_KEY, every sector and risk line, and the WhatsApp text, which is rebuilt. That covers every row MARKET_STORE writes. The analyst's Review path is still open (SA-15).
- **Unchanged from round 1.** Identity comes from the session only. The role→action map is checked server-side, and the subscriber role holds no actions. All SQL uses `$n` placeholders. Custom UI has no raw HTML, `innerHTML`, `href` or `window.open` (re-grepped). `npm audit`: 0 vulnerabilities. Security headers: **observed**.
