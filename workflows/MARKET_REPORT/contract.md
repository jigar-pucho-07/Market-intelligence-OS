# MARKET_REPORT
trigger: `webhook.catch_webhook` {}
constants: `{"news_limit": 40, "summary_chars": 300, "dedupe_chars": 60, "max_age_hours": 48, "auto_send": true}`
writes: reports, news_articles, audit_log

Shape: trigger → `step_constants` → [`step_router` on action →] `step_<action>_ai` → `step_<action>_build` (parse + row, CODE) → `step_<action>_insert|update` (http → the app's /api/data, named fields under body.data) → `step_<action>_done` (Return: ok, id, row).
Built by `scripts/build_flows.py` (flow/flowkit.py); the JSON lands beside this file as `MARKET_REPORT.json`; the CHECKLIST carries a test payload per action.

### `run`  (model: none, ~45s, ~6 credits, 22 runs/month)
payload: `{"Trigger": "string", "Report_ID": "string"}`
result: `{"Report_ID": "string", "Status": "string", "Articles_Analyzed": "number"}`
rules: The door (owner fix round 1, SA-01..03): ?k= secret checked first (401), action validated (400), today's report state read before any spend (a scheduled run with today Ready/Sent → 409; a manual run or rerun regenerates today's report whatever its Status; rerun of another day → 409) → POST MARKET_ANALYSE ?k=. Steps below run in MARKET_ANALYSE; Five RSS fetches run as separate steps; a failed or empty source yields 0 items and is reported in Source_Status, never stops the run (CODE); Parse <item> title / description (CDATA or plain, HTML stripped, ≤300 chars) / pubDate / link; dedupe on the first 60 lower-cased alphanumeric title characters; categorise with word-bounded keyword rules in the source's order; keep 40 (CODE — fixes S2, S3); Impact: HIGH when the title names RBI, repo, Fed, FII, GDP, CPI, inflation, SGX/GIFT Nifty or a ≥ $1 billion deal; MED for Banking, IT, F&O, Benchmark; else LOW (CODE); ONE AI call (Studio llm-ai, model class standard, temperature 0.3, 2,000 tokens) under the DATA RULE: senior Indian market analyst, COMMENTARY ONLY — sentiment, confidence, drivers, segment outlooks with the range in focus, F&O positioning view, sectors POSITIVE / WATCH / NEGATIVE, risks HIGH / MED, a market view per trader type; never a buy/sell call, strike, target or stop-loss (owner decision on SEBI). Prompt: app/src/custom/lib/market.js buildPrompt(); Zero articles, or model JSON missing Sentiment / Confidence_Level / Driver_1 → Status Failed with Error_Message, never a half-empty Ready row (CODE + router on the parse field); The model's JSON is parsed and only declared keys are kept; enum values outside the lists become empty; confidence clamped 0–100 (CODE); WhatsApp_Message = header (day, date, report time IST) + analysis + footer 'Market Opens: 9:15 AM IST' + disclaimer, trimmed to 4,000 characters (CODE, app/src/custom/lib/market.js — the same formatter the app's preview uses); One report per Report_Date (unique). A payload Report_ID, or a manual run, re-runs today's row in place (PATCH; Failed / Ready / Sent → Ready); a re-run that fails never replaces a Ready or Sent report (RERUN_FAILED). The report is written first, then news_articles with deterministic ids (Report_ID + dedupe key) so a re-run never doubles them; Last step: POST BROADCAST — always for Failed (the admin alert), for Ready only on the 06:00 scheduled run when constants.auto_send is true (a manual run stays Ready until sent from the app); then POST /api/jobs/<id> done

### `rerun`  (model: none, ~45s, ~6 credits, 8 runs/month)
payload: `{"Report_ID": "string"}`
result: `{"Report_ID": "string", "Status": "string", "Articles_Analyzed": "number"}`
rules: The same pipeline as run, on an existing Failed report: fetch → analyse → PATCH that Report_ID Failed → Ready (or Failed again with the new error); a Sent report is refused
